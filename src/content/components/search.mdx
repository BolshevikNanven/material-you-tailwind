## Installation

### Shadcn CLI

```bash
npx shadcn@latest add @material-you/search
```

### Manual installation

- Copy and paste the following code into your project
    <ComponentSource title='src/components/ui/search.tsx'>
        <Search />
    </ComponentSource>

## Usage

```tsx
import { Avatar, AvatarFallback } from '@/components/ui/avatar'
import {
    ListItemContent,
    ListItemLabel,
    ListItemLeading,
    ListItemSupportingText,
    ListItemTrailing,
    ListItemTrailingText,
} from '@/components/ui/list'
import { Search, SearchInput, SearchList, SearchListItem, SearchTrigger } from '@/components/ui/search'
```

`Search` is a compound component. `SearchTrigger` renders its children while closed. Once open, it hides those children and renders the Material search view header with built-in back and clear buttons.

The first direct `SearchInput` child of `SearchTrigger` is reused in the open header, so you can keep value, default value, placeholder, and change handlers on the input.

```tsx
<Search variant='docked'>
    <SearchTrigger>
        <span data-slot='search-icon'>
            <i className='icon-[material-symbols--search-rounded]' />
        </span>
        <SearchInput placeholder='Search' />
        <button data-slot='search-button' type='button' aria-label='Voice search'>
            <i className='icon-[material-symbols--mic-rounded]' />
        </button>
    </SearchTrigger>
    <SearchList>
        <SearchListItem>
            <ListItemLeading>
                <Avatar className='size-10 bg-surface-container-high'>
                    <AvatarFallback>
                        <i className='icon-[material-symbols--category-rounded]' />
                    </AvatarFallback>
                </Avatar>
            </ListItemLeading>
            <ListItemContent>
                <ListItemLabel>Label text</ListItemLabel>
                <ListItemSupportingText>Supporting line text, lorem ipsum dolor</ListItemSupportingText>
            </ListItemContent>
        </SearchListItem>
    </SearchList>
</Search>
```

## Variants

### Docked

Docked search opens a list surface directly below the trigger, matching Compose `ExpandedDockedSearchBarWithGap`: a 2px gap and 12px corners, the width of the `Search` root, and a scrim behind it that closes search when clicked. The list is at least 240px tall (never taller than half of the viewport) and scrolls once its content exceeds half of the viewport height.

Set the width on `Search` or a parent layout. The component does not apply a max width.

```tsx
<Search className='w-[360px]' variant='docked'>
    <SearchTrigger>
        <span data-slot='search-icon'>
            <i className='icon-[material-symbols--search-rounded]' />
        </span>
        <SearchInput placeholder='Search' />
    </SearchTrigger>
    <SearchList>
        <SearchListItem>Result</SearchListItem>
    </SearchList>
</Search>
```

Docked search closes automatically when focus leaves the entire search area, including the list.

### Fullscreen

Fullscreen search matches Compose `ExpandedFullScreenContainedSearchBar`. The trigger becomes a fixed pill, inset 8px horizontally and 4px from the top, above a full-screen result surface on `surface-container-low`. There is no divider.

```tsx
<Search variant='fullscreen'>
    <SearchTrigger>
        <span data-slot='search-icon'>
            <i className='icon-[material-symbols--search-rounded]' />
        </span>
        <SearchInput placeholder='Search full screen' />
    </SearchTrigger>
    <SearchList>
        <SearchListItem>Result</SearchListItem>
    </SearchList>
</Search>
```

## Trigger Content

Closed trigger content is fully slotted by children. Use `data-slot="search-button"` for 48px icon buttons and `data-slot="search-icon"` for non-interactive 48px icon targets that match the Material search bar layout.

```tsx
<SearchTrigger>
    <span data-slot='search-icon'>
        <i className='icon-[material-symbols--menu-rounded]' />
    </span>
    <SearchInput placeholder='Hinted search text' />
    <button data-slot='search-button' type='button' aria-label='Voice search'>
        <i className='icon-[material-symbols--mic-rounded]' />
    </button>
</SearchTrigger>
```

Buttons and links inside closed trigger content do not open search when clicked or focused. Add `data-search-no-open` to any custom interactive element that should also avoid opening search.

## Result Items

`SearchListItem` wraps the [List](/docs/components/list) `ListItem` on a transparent container, inset 4px vertically, so the content lines up with the search bar icons. Build each row with the `ListItemLeading`, `ListItemContent`, `ListItemLabel`, `ListItemSupportingText`, `ListItemTrailing` and `ListItemTrailingText` parts from the list component.

```tsx
<SearchListItem closeOnSelect={false}>
    <ListItemLeading>
        <Avatar className='size-10 bg-surface-container-high'>
            <AvatarFallback>
                <i className='icon-[material-symbols--category-rounded]' />
            </AvatarFallback>
        </Avatar>
    </ListItemLeading>
    <ListItemContent>
        <ListItemLabel>Label text</ListItemLabel>
        <ListItemSupportingText>Supporting line text, lorem ipsum dolor</ListItemSupportingText>
    </ListItemContent>
    <ListItemTrailing>
        <ListItemTrailingText>Meta</ListItemTrailingText>
    </ListItemTrailing>
</SearchListItem>
```

By default, selecting a result closes search. Use `closeOnSelect={false}` to keep it open.

## API Reference

### Search

| Prop         | type                      | default  |
| :----------- | :------------------------ | :------- |
| variant      | `docked` \| `fullscreen`  | `docked` |
| open         | `boolean`                 |          |
| defaultOpen  | `boolean`                 | `false`  |
| onOpenChange | `(open: boolean) => void` |          |
| disabled     | `boolean`                 | `false`  |

### SearchTrigger

| Prop     | type                      | default |
| :------- | :------------------------ | :------ |
| onSearch | `(query: string) => void` |         |

`SearchTrigger` also accepts standard `form` props.

### SearchInput

| Prop          | type                      | default              |
| :------------ | :------------------------ | :------------------- |
| placeholder   | `string`                  | `Hinted search text` |
| value         | `string`                  |                      |
| defaultValue  | `string`                  |                      |
| onValueChange | `(value: string) => void` |                      |

`SearchInput` also accepts standard `input` props except `type`; it always renders `type="search"`.

### SearchList

| Prop             | type      | default |
| :--------------- | :-------- | :------ |
| forceMount       | `boolean` | `false` |
| contentClassName | `string`  |         |

### SearchListItem

| Prop          | type      | default |
| :------------ | :-------- | :------ |
| selected      | `boolean` | `false` |
| closeOnSelect | `boolean` | `true`  |
| asChild       | `boolean` | `false` |

`SearchListItem` also accepts the `ListItem` props (such as `disabled` and `asChild`) except `selectable`, `dragged` and `interactive`.
